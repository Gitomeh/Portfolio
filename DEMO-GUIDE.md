## 2:30–3:30 — Design Decision

**What to say:**
"One key design decision I made was to use a single-file architecture with inline CSS and JavaScript rather than separating files. This makes the portfolio extremely easy to deploy — you can simply open the HTML file in any browser or upload it to any static hosting service without build tools or dependencies. While this approach limits scalability for larger applications, it's perfect for a personal portfolio that needs to be simple, fast, and maintainable. The trade-off is that as the site grows, I may eventually want to separate concerns for better maintainability."

However, I personally reviewed all generated code, tested the portfolio across multiple browsers, verified responsive behavior on different screen sizes, and made all final decisions on design and functionality. ## 4:15–5:00 — Limitation

**What to say:**
"One genuine limitation of this portfolio is that the contact form doesn't actually send emails — it shows an alert message instead. This is because there's no backend integration. To make it fully functional, I would need to add a backend service or integrate with a form handling service like Formspree or EmailJS. Another limitation is that some project links are placeholders rather than actual live demos, which I plan to address as I deploy more projects. Going forward, I'd like to add proper analytics to track visitor engagement and optimize the images for better performance."

## Preparation Notes

**Before recording:**
- Ensure the portfolio is running locally or on a live server
- Test all navigation links work correctly
- Verify images load properly
- Check responsive behavior (test on mobile if possible)
- Have the contact form ready to demonstrate
- Practice the timing to stay within 3–5 minutes

**Technical requirements:**
- Modern web browser
- Internet connection (for Font Awesome icons and external links)
- Optional: Local server or live deployment

**What NOT to do:**
- Don't claim features that don't exist
- Don't show broken links as working
- Don't invent functionality
- Don't claim the video already exists (this is preparation for recording)
